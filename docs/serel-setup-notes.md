# Serel setup and maintenance

Serel tooling is already installed; [installation provenance](serel-installation.md) records the pinned versions. A clone needs no framework reinstall merely because its local memory bank is absent.

- Preserve installed adapters, receipts, license notices and customized workflows.
- Keep hooks off unless explicitly enabled by the developer.
- Initialize local continuity from the code and `PRD.md` through `init-memory`. Preserve populated files in a partial bank; do not silently reseed.
- Store the bank and raw observations only in their ignored local paths. Review and sanitize durable findings before moving them into public docs.
- `polish` proposes a diff; applying it is a separate edit. Do not change requirements or evidence through wording changes.
- `verify-map` records actual Launch, Drive, Observe and Clean up steps. Keep observation records separate from recipes; a passing mock is not a manual observation.
- Run Memory's drift/retention checks after changes. They do not prove semantic correctness or OS behavior.

For upgrades, inspect official upstream instructions and version changes before executing an installer. Use the existing-project, non-clobbering workflow and do not bypass a genuine file collision. Kit requires installed Memory and an initialized local bank for verification workflows. Preserve upstream license notices.

Official pinned references: [Memory v0.6.0](https://github.com/madeordinary/serel-memory/tree/v0.6.0) and [Kit v0.2.0](https://github.com/madeordinary/serel-kit/tree/v0.2.0). The newer combined setup guide is separate from the installed release; do not assume newer behavior is installed.
